# NMD-530 금속검출 수신부 — 설치 가이드

금속검출기(NMD-530) 수집기가 보내는 검출·통신끊김 이벤트를 스마트팩토리 시트에 자동 적재하는 웹앱.
코드: [`nmd530_receiver.gs`](./nmd530_receiver.gs) · 계약: [`../docs/NMD530_PIPELINE.md`](../docs/NMD530_PIPELINE.md)

> **Tuya 로거와 별개의 새 Apps Script 프로젝트**로 만든다(자격증명·배포 분리).
> 토큰·`/exec` 주소·시트 ID 는 **채팅·깃·문서에 붙이지 말 것** (이 저장소는 public).
> 구글 로그인·권한 승인·토큰 입력은 사용자 본인이 한다.

---

## 1. 새 Apps Script 프로젝트 만들기
1. 브라우저에서 https://script.google.com 접속 → 시트 소유 계정으로 로그인.
2. 왼쪽 위 **＋ 새 프로젝트** 클릭.
3. 화면 위 **제목 없는 프로젝트**를 클릭 → 이름 `스마트팩토리 금속검출 수신부` 입력 → **이름 바꾸기**.

## 2. 코드 붙여넣기
4. 편집기 왼쪽 파일 목록에서 `코드.gs`(Code.gs) 선택 → 내용 전체 삭제(Ctrl+A → Delete).
5. [`nmd530_receiver.gs`](./nmd530_receiver.gs) 파일 전체를 복사해 붙여넣기 → 저장(💾 또는 Ctrl+S).

## 3. 토큰 만들기 (내 PC)
6. 윈도우 **시작 › PowerShell** 실행 후 아래 한 줄을 붙여넣고 Enter:

   ```powershell
   $b=New-Object byte[] 32; [System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)
   ```
7. 출력된 한 줄(44자 안팎)이 토큰이다. **메모장 등 안전한 곳에만** 두고, 4절(9단계)에서 쓴다. 수집기 설치(7절, 17단계)에서도 같은 값을 입력한다.

## 4. 스크립트 속성 입력
8. 편집기 왼쪽 **⚙ 프로젝트 설정** 클릭 → 아래로 내려 **스크립트 속성** → **스크립트 속성 추가**.
9. 아래를 한 줄씩 입력(속성 / 값) 후 **스크립트 속성 저장**:

   | 속성 | 값 |
   |---|---|
   | `NMD530_TOKEN` | 6단계에서 만든 토큰 |
   | `SHEET_ID` | 스마트팩토리 스프레드시트 ID — 시트 주소 `…/d/<여기>/edit` 의 `<여기>` 부분 |
   | `NMD530_DEVICES` | *(선택)* 허용 기기 이름. 예 `NMD530-1` (콤마로 여러 개). 비우면 기기 검사 안 함 |

## 5. 웹 앱으로 배포
10. 편집기 오른쪽 위 **배포 › 새 배포** 클릭.
11. **유형 선택(⚙) › 웹 앱** 선택.
12. 설명에 `v1` 입력, **다음 사용자로 실행: 나**, **액세스 권한이 있는 사용자: 모든 사용자** 선택 → **배포**.
13. 권한 승인 창이 뜨면 **액세스 승인** → 계정 선택 → *확인되지 않은 앱* 경고가 나오면 **고급 › (프로젝트 이름)(안전하지 않음)으로 이동 › 허용**. (스프레드시트 접근 권한 1회)
14. 배포 완료 창의 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 **복사**해 안전한 곳에 둔다.

## 6. 건강 확인
15. 브라우저 새 탭에 14단계 주소를 붙여넣고 Enter.
16. 화면에 `{"service":"nmd530_receiver","ok":true}` 가 보이면 정상. (데이터 없음 — 살아 있는지만 확인)

## 7. 수집기에 주소·토큰 넣기
17. 수집 PC(DEV-0007)에서 `bridge/windows/nmd530-bridge-install.ps1` 을 관리자 PowerShell 로 **`-NoStart` 를 붙여** 실행 — 작업을 **등록만 하고 시작하지 않는다**(아래 시험을 먼저 하기 위해). 설치 스크립트가 **주소(14단계)** 와 **토큰(6단계)** 을 물어본다. 붙여넣고 Enter. (현장 순서 전체 = [`DEV0007_NMD530_INSTALL_GUIDE.md`](../docs/DEV0007_NMD530_INSTALL_GUIDE.md))
    (값은 `C:\ProgramData\maytutu\nmd530\` 에 저장되며 Users 읽기는 제거된다. 토큰은 명령행 플래그가 아니라 환경변수/설정 파일로만 받는다.)

## 8. 시험 순서 (실제 시트에 쓰므로 이 순서를 지킨다)
18. **드라이런**: 수집 PC 에서 수집기를 `--dry` 로 실행 → 전송하지 않고 출력만 나온다. 이벤트 JSON(구분·시각 `+09:00`)이 정상인지 눈으로 확인.
19. **실전 1건**: `--dry` 없이 **같은 창에서 직접** 실행(`node nmd530-bridge.js --config C:\ProgramData\maytutu\nmd530\config.json`)해 `COLLECTOR_START` 1건과 heartbeat 가 한 번 전송되게 한 뒤 `Ctrl+C` 로 끈다. 작업(17단계)은 아직 시작하지 않은 상태여야 한다 — 검출기에 접속하는 것이 하나뿐이어야 한다(접속 1개 제한은 가정).
20. **되읽기**: 스마트팩토리 시트를 열어 아래 두 탭에 행이 생겼는지 확인.
    - `금속검출로그` — 1행 헤더 + `수집기시작` 1행 (서버수신시각 열이 현재 시각)
    - `금속검출상태` — 헤더 + 기기 1행 (통신 `UP`)
    - 안 생겼으면 9절 문제 해결 표로.
21. **중복 방지 시험**: 수집기를 다시 실행하면 부팅ID 가 새로 만들어져 이벤트ID 가 달라지므로(`수집기시작` 행이 하나 더 생기는 것이 정상) "한 번 더 실행"은 시험이 못 된다. 대신 **같은 요청 본문을 두 번** 보낸다 — 편집기 위쪽 함수 선택에서 `nmd530_selfTest` 를 골라 **실행**하고, 아래 **실행 로그**에서 `nmd530 selfTest 1차=…` 가 `"saved":2`, `2차=…` 가 `"saved":0,"dup":2` 인지 확인한다. 이 함수는 `금속검출로그`에 이벤트ID 가 `SELFTEST|` 로 시작하는 시험 행 2건을 남긴다 — **합격을 확인한 뒤 지운다**(안 지우면 화면에 «수집기시작» 으로 보인다).
22. **테스트 피스 1회**: 검출기에 시편(테스트 피스)을 한 번 통과시킨다 → 약 3~60초 뒤 `금속검출로그`에 구분 `검출` 1행(증가분 1)이 생기는지 확인.
23. 여기까지 맞으면 **그다음 상시 가동**으로 넘어간다 — `Start-ScheduledTask -TaskName Maytutu-NMD530-Bridge` 로 17단계에서 등록만 해 둔 작업을 시작하고, 설치 가이드 5번의 «전원 껐다 켜기» 시험까지 마친다.

## 9. 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| 응답 `{"ok":false,"error":"auth"}` | 토큰 불일치. 스크립트 속성 `NMD530_TOKEN` 과 수집기 설정의 토큰이 같은지(앞뒤 공백·줄바꿈 포함) 다시 확인 |
| `error: "bad_request"` | 본문 형식 오류, 이벤트 200건 초과, `v` 가 1 아님, 또는 `NMD530_DEVICES` 에 없는 기기 이름 |
| `error: "server"` | 수신부 내부 오류(락 대기 초과·시트 접근 실패 등). 편집기 왼쪽 **실행** 메뉴의 로그에서 `nmd530 doPost 오류` 확인 |
| 전송 직후 HTML 이 돌아옴(302 후) | 정상 동작이다 — Apps Script 는 처리 후 302 로 응답한다. 수집기가 확인하지 못하면 스풀에 두고 같은 이벤트ID 로 재전송하며, 수신부가 중복을 걸러 준다 |
| 시트에 행이 없음 | `SHEET_ID` 오타, 또는 5절 배포 계정에 그 시트 편집 권한이 없음. 시트 공유에서 배포 계정을 편집자로 추가 후 재시도 |
| 코드를 고친 뒤 반영 안 됨 | **배포 › 배포 관리 › 연필(편집) › 버전: 새 버전 › 배포**. `/exec` 주소는 그대로 유지된다 |
| 권한 승인을 다시 요구 | 스크립트를 편집기에서 한 번 실행해 승인하거나 5절 13단계를 반복 |

## 위험·한계
- 웹 앱은 **익명 접근**이라 토큰이 유일한 방어다. 토큰이 틀리면 수신부는 시트를 열지도 않고 `auth` 만 돌려준다.
- 요청 한 번에 이벤트는 200건까지, 중복 검사는 `금속검출로그` 끝 5000행 안에서만 한다.
- `금속검출로그`는 **시간 오름차순 그대로** 둔다 — 정렬하거나 행을 재배치하면 "끝 5000행"의 뜻이 바뀌어 중복 적재가 생길 수 있다. 보관은 위쪽 오래된 행만 잘라 다른 탭으로 옮기고 최근 5000행은 남긴다. 정렬이 필요하면 필터 보기를 쓴다.
- 이 기록은 검출기가 센 검출(리젝트) 수를 수집 PC 시계 기준으로 적는 것이며, 시편 감도 확인(CCP-1P 수기 일지)을 대체하지 않는다.

### 토큰이 새었을 때 교체
1. 3절(6~7단계)로 **새 토큰**을 만든다.
2. 스크립트 속성 `NMD530_TOKEN` 값을 새 토큰으로 바꾸고 저장 — 즉시 옛 토큰은 `auth` 로 거부된다.
3. 수집 PC 의 설정(7절 17단계에서 저장된 토큰)을 새 토큰으로 바꾸고 수집기를 다시 시작한다. 그동안 이벤트는 스풀에 쌓였다가 복구 후 전송된다.
4. 주소(`/exec`)까지 새었다면 **배포 › 배포 관리 › 보관처리** 후 5절부터 새로 배포하고 수집기의 주소도 교체한다.
