> **목적**: 앙호두 생산라인 금속검출기(**GNI NMD-530**)의 실시간 데이터(누적 생산량·검출/리젝트 수·검출 시각 로그)를
> 사내 스마트팩토리(HACCP)에 자동 연동. 현재 수기 입력 중인 금속검출 CCP를 장비 실측으로 자동 기록.
> **상태(2026-07-03)**: 타당성 확인 완료 + 프로토콜 코덱·연결도구 구현·검증 완료. **남은 것 = 브리지 상시 프로그램(→Sheets) + 웹 화면.**

## 1. 핵심 결론

- **연동 가능.** 단, 브라우저 웹앱(GitHub Pages 정적)·Apps Script(구글 클라우드) **어느 쪽도 검출기에 직접 붙을 수 없음**

- 해결책 = **사내망 상시 노트북에 "브리지" 프로그램 1개**. 검출기에 TCP 접속·파싱 → Google Sheets 적재.
  이미 가동 중인 **Tuya 온도센서 연동과 동일 구조** (`apps-script/tuya_temp_logger.gs` 참조).

```

[상시 노트북] 브리지(Node.js) : TCP접속→프레임파싱→POST
   └─▶ Apps Script doPost ─▶ Google Sheets '금속검출로그' ─▶ 스마트팩토리 웹앱 표시
```

## 2. NMD-530 프로토콜 요점 (원문: `C:\Users\dogan\Downloads\NMD530_Packet_Define(Ethernet)_20241017.doc`)

- **물리**: Ethernet **TCP/IP 소켓**, **MD=서버 / PC=클라이언트**(PC가 장비로 접속). 장비에 IP·포트 설정됨.
- **프레임**: `STX(0x02) | LENGTH(2,BE) | CMD(1) | DATA(n) | ETX(0x03) | LRC(1)`
  - LENGTH = STX~LRC 전체 바이트 수(=6+dataLen). LRC = STX~ETX XOR.
  - 검증된 실제 예시(상태조회): `02 00 06 33 03 34`.
- **수치 바이트순서**: Big-Endian. **예외**: 대량이력 AP.021/AP.022는 Little-Endian(문서 2020-12-02 "Endian 수정"). 실시간용 AP.005/AP.023은 BE.
- **주요 CMD**: `0x33` 상태조회(PC→MD) / `0x35` 상태보고(MD→PC, AP.005) / `0x2A` 버전 / `0x3A` 검출이력(대량, **작업시간 외 권장**) / `0x60` 제품변경.
- **실시간 채널**: `0x33` 주기 폴링 → `0x35`(AP.005) 응답. + 검출 시 MD→PC 이벤트 푸시.

**AP.005 상태보고(12B, BE)**: 제품번호(1) · 상태비트(1, AP.103) · Ch1/Ch2 Peak(각1) · Ch1/Ch2 검출레벨(각1) · **누적생산량(4)** · **누적검출량(2)**
**AP.023 검출로그(17B, BE)**: subCmd(1) · LOG TYPE(1: 0검출/1역주행/2전원on) · 제품번호(1) · **검출시각(6: YY MM DD HH MM SS)** · 검출카운트(2) · 제품카운트(3) · NULL(3)
**AP.103 상태비트**: 0x02 Out error · 0x04 Bal error · 0x08 테스트모드 · 0x10 듀얼주파수 · (0x01,0x20 예약)

## 3. 네트워크 구성 결정 (확정)

- 검출기 = **이더넷 포트만** 있음. 사내 **와이파이망**에 올려야 함. 상시 노트북은 와이파이에 있음. 검출기 **1대**.
- **기기에 무선 랜카드(USB동글) 설치 = 불가** (임베디드 장비, 드라이버 없음).
- 채택: **USR-W610(산업용 이더넷↔와이파이 컨버터)을 브리지 모드로 사용.**
  - 근거: PUSR 공식 — *"브리지 모드에서 이더넷 포트 연결 기기는 상위 네트워크에 직접 연결된 것과 동등, W610은 투명."*
  - 대안(상황별): ① 검출기→공유기 **랜선 직결**(공유기 근처면 최선) ② 노트북 근처면 **검출기↔노트북 랜선 직결**+노트북 와이파이 업로드(USB-이더넷 젠더) ③ **메시 서브공유기 LAN포트**에 연결(메시/AP모드 필수, 이중NAT 금지).
- **공통 함정**: 검출기 **IP 고정**(DHCP예약) · **AP 클라이언트격리 OFF** · 노트북/검출기 **동일 IP대역** 확인 · W610은 **2.4GHz**.

### USR-W610 설치 순서
1. W610 전원만 켬 → 노트북 와이파이에서 **`USR-W610_XXXX`** 접속.
2. 브라우저 **`10.10.100.254`** (ID/PW `admin`/`admin`).
3. **STA Interface Setting**: AP's SSID=사내 2.4G SSID, Password=와이파이 비번, DHCP=Enable.
4. **Ethernet Setting**: 이더넷 포트=**LAN Port**(브리지). 시리얼 메뉴는 손대지 않음.
5. **Save → Restart**.
6. **검출기 이더넷 ── 랜선 ── W610 이더넷** 연결.
7. 검출기 IP 확인(검출기 설정화면 또는 공유기 기기목록) → **DHCP 예약으로 고정** → TCP 포트도 확인.

## S2. 배선 (RS-232 3선)

| 신호 | 저울(DB9 DTE 기준) | W610 | 결선 |
|---|---|---|---|
| TXD | 2번 | RXD | **교차** (저울TXD→W610RXD) |
| RXD | 3번 | TXD | 저울RXD←W610TXD |
| GND | 5번 | GND | 직결 |

- 저울은 **보내기만** 하므로 실무상 **TXD+GND 2선**이면 동작.
- ⚠️ 핀 배열은 제조사마다 다름. **안 되면 2↔3 교체**가 표준 트러블슈팅.
- 전력선과 분리 포설(모터·인버터 노이즈), GND 공통.

  시도 순서(9600-8-N-1 → 4800 → 2400 → 19200 → 38400 / 7비트면 `--strip-high-bit`)를 출력한다.

### 기록 판정 로직 (핵심)
충진은 **매번 같은 값(5kg)** 이 반복되므로 "값이 바뀔 때만 기록"하면 2봉째부터 누락된다.
그래서 **사이클 게이트**로 처리: `빈 저울/불안정 → 기록준비` / `안정 N회 + 유효중량 → 1건 기록 후 잠금`.
→ 자체검증에 "2봉째도 기록(같은 값 반복)" · "비우기 전엔 중복기록 안 함" 케이스 포함.

```bash
node scale-codec.js --selftest                  # 파서 검증
node scale-probe.js --mock 18899                # 가짜 저울(터미널 A)
node scale-probe.js 127.0.0.1 18899             # probe(터미널 B) — 계량 시나리오 확인
node scale-probe.js <W610_IP> 8899              # 실장비 (--raw 로 원문덤프, --unit=g 로 기본단위)
```

**HACCP 원칙**: `ST`(안정)일 때의 값만 기록에 쓴다. `US`(불안정)는 흔들리는 중이라 기록 금지.
상태 판정은 **불안정 우선(fail-safe)** — Mettler `S D` 처럼 앞 토큰이 응답코드인 형식 때문.

## S5. 앱 연동 설계 (2트랙)

브라우저는 사내 TCP에 직접 못 붙으므로(HTTPS 혼합콘텐츠·raw TCP 불가) **Sheets 중계**로 간다.

| 트랙 | 동작 | 용도 |
|---|---|---|
| **실시간** | 브리지가 `계량_실시간` 시트 **1행 덮어쓰기** | 앱 3~5초 폴링 → "현재 중량" 표시 |
| **확정** | 작업자가 앱에서 **"이 값으로 확정"** | `계량기록` **append** → 배합·LOT 연결 |

- 연속 스트림을 그대로 append 하면 시트가 폭발한다 → **안정 + 값 변화 시에만** 처리.
- 작업자 확정 행위가 들어가야 "언제 계량한 값인지"가 기록에 남는다(추적성).
- 예상 지연: 저울→표시 **3~6초**.
