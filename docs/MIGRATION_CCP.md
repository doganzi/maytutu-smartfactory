# P4 — 구 7단계 금속검출 기록 → 신 격자(ccpGrid-v1) 이관 로그

> 실행 2026-06-11 · 대상 시트 `공정기록`(`stepType='inspect'`) · 실행자 my_ro@anghodu.biz (HQ Admin)
> 선행: PR #70 (상세뷰 `ccpGridReadView` 격자 렌더) 머지·배포 후 실행. SPEC: [`CCP_SPEC.md`](./CCP_SPEC.md) §6.

## 배경
#66(입력)·#67(PDF)은 금속검출 CCP를 종이양식 격자(`ccpGrid-v1`)로 전환했으나 **기존 기록은 구 7단계 `stepData`**(`step1Time/step2/step3/step4Time/step5/step6/ccpTotal`)로 남아, 작업지시서 상세화면이 옛 양식(검사수량·합격/불합격)으로 표시됐다. 본 이관으로 기존 기록도 격자로 표시·PDF 출력된다.

## 변환 규칙 (`migrate7stepToGrid`, index.html)
| 구 7단계 | → 신 격자 `checks` 행 |
|---|---|
| step1Time / step2(시편Fe·SUS) / step3(제품+시편) | `작업시작전` 1행 (시편 합격→검출, 위치 좌중우 동일값) |
| step5[N] (2시간 검증) | `작업중2h` N행 |
| step6 (최종 시편) | `작업종료` 1행 |
| ccpTotal | 통과량 `N개` |
| 위치값(좌중우·상하)·제품통과 (구형에 없음) | 정상 기본값(시편=검출, 제품통과=불검출, 제품+시편=검출) |

`판정`은 행별 `ccpRowJudge`로 자동 재계산. 신 객체에 `_migrated:'7step'`·`_migratedAt`(ISO) 태깅, **원본 stepData 문자열은 `_legacy7`에 그대로 보존**(롤백/감사용).

## 절차 (드라이런 → 변환 → 검증)
1. **드라이런**(쓰기 없음): 56건 inspect 중 변환대상 55건, 전부 판정 적합, 파싱오류·미상형식·부적합 0건, 빈 stepData 1건(`WO-20260417-001`) 제외 확인.
2. **변환**: 각 행을 **행 인덱스(`공정기록!F{rowIdx}`)로 정밀 지정** 업데이트(`공정기록` col[0]은 WO id라 검색 키 사용 불가). `SheetsAPI.batchUpdate` 1콜(50청크).
3. **검증**(재조회): 변환 55건 전부 `_fmt==='ccpGrid-v1'` + `checks.length>0` + `_legacy7` 존재 확인 → **55/55 PASS, 실패 0**.
4. **종단 검증**: 배포된 `ccpGridReadView`로 `WO-20260611-002` 렌더 → 격자 정상(체크리스트 깨짐 0)·통과량 40개·판정 적합·변환본 표기 확인.
