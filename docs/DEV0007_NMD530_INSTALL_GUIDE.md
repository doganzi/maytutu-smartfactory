## 가이드 1

표시: **[현장 확인]** = 지금 확인된 사실이 아니라 현장에서 보고 알려줘야 하는 것.

### 1. 준비물과 확인
1. DEV-0007 이 계속 켜져 있을 수 있는 상태인가 — 아래 **전원·시계·Wi-Fi 사전 점검 (필수)** 7가지를 모두 확인한다 — **[현장 확인]**
2. DEV-0007 이 공장 Wi-Fi 에 연결돼 있고 인터넷이 되나 (본사는 공장 LAN 에 붙어 있던 기록만 안다 — **[현장 확인]**)
3. QR 라벨프린터·송장 라벨프린터가 지금 정상 출력되나. 연결 방식(USB/네트워크)을 적어 둔다 — **[현장 확인]**
4. 검출기 쪽 전용 연결 장치(와이파이 브리지 USR-W610)에 전원이 들어와 있고 불이 켜져 있나. 검출기와 랜선이 꽂혀 있나.
5. 시작 메뉴 → 「PowerShell」 검색 → **마우스 오른쪽 → 관리자 권한으로 실행**. 파란 창에 입력:
```powershell
node -v
```
   - `v22.…` 처럼 숫자가 나오면 → 2번 건너뛰고 3번으로. (`v18` 미만이면 2번으로 — 설치 스크립트가 낮은 버전을 막는다.)
   - 「인식되지 않습니다」 라고 나오면 → 2번 진행. (Node.js 설치 여부 — **[현장 확인]**)

**전원·시계·Wi-Fi 사전 점검 (필수 — 설치 스크립트는 이 설정들을 바꾸지 않는다)**
DEV-0007 이 절전·최대 절전에 들어가거나 업데이트로 재시작되면 그 시간 동안 수집이 멈춘다. 멈춘 동안의 검출은 시각이 남지 않는 «모니터링 공백» 으로만 남을 수 있다. 아래 7가지를 눈으로 확인하고 결과를 적어서 본사에 알려 준다 — 모두 **[현장 확인]** (확인 전에는 상시 전원이라고 가정하지 않는다).
1. **충전기 상시 연결**: 충전기가 꽂혀 있고 작업표시줄 배터리 아이콘에 플러그 표시가 있나.
2. **연결 시 절전 안 함**: 설정 → 시스템 → 전원 및 배터리 → 「화면 및 절전」 에서 「전원 연결 시 PC 절전 모드로 전환」 이 **안 함** 인가. (화면 끄기는 그대로 둬도 된다.)
3. **덮개를 닫아도 동작**: 제어판 → 하드웨어 및 소리 → 전원 옵션 → 「덮개를 닫을 때 수행할 동작 선택」 에서 「전원 연결 시」 가 **아무 것도 안 함** 인가.
4. **Windows 업데이트 자동 재시작 시간대**: 설정 → Windows 업데이트 → 고급 옵션 → 「사용 시간」 이 공장 가동 시간을 덮고 있나. 재시작되면 수집기는 부팅 뒤 자동으로 다시 시작하지만(지연 60초) 그 사이는 공백이다.
5. **빠른 시작 끄기**: 제어판 → 하드웨어 및 소리 → 전원 옵션 → 「전원 단추 동작 선택」 → 「현재 사용할 수 없는 설정 변경」 → 「빠른 시작 켜기」 체크가 **해제**돼 있나. (켜져 있으면 «종료» 가 완전한 종료가 아니라 최대 절전에 가까워, 부팅 시각이 기록과 어긋날 수 있다.)
6. **Wi-Fi 자동 연결과 절전**: 설정 → 네트워크 → Wi-Fi → 「알려진 네트워크 관리」 에서 공장 Wi-Fi 의 「범위 안에 있을 때 자동으로 연결」 이 켜져 있나. 장치 관리자 → 네트워크 어댑터 → Wi-Fi 어댑터 → 속성 → 전원 관리 → 「전원을 절약하기 위해 컴퓨터가 이 장치를 끌 수 있음」 이 **해제**돼 있나. (수집기는 로그인 전에 시작되므로, Wi-Fi 가 «이 사용자에게만» 저장돼 있으면 로그인 전에는 붙지 못할 수 있다 — 5번 시험의 4단계가 이것을 확인한다.)
7. **PC 시계**: 설정 → 시간 및 언어 → 날짜 및 시간 → 「시간 자동 설정」 이 켜져 있고 시간대가 **(UTC+09:00) 서울** 인가. (모든 기록 시각은 이 PC 시계를 쓴다.)

### 2. Node.js 설치 (위에서 없다고 나왔을 때만)
1. 공식 사이트(nodejs.org)에서 **LTS** 설치 파일을 내려받는다.
2. 내려받은 파일을 두 번 클릭 → 「Next」만 눌러 끝까지 → 「Finish」.
3. PowerShell 창을 **닫고 다시 관리자로 열어** `node -v` 를 입력해 숫자가 나오는지 본다.

### 3. 파일 가져오기
1. 본사가 보낸 압축 파일(zip)을 `<받은 위치>` 에서 찾는다.
2. 마우스 오른쪽 → 「압축 풀기」 → 폴더 `C:\nmd530-src` 로 푼다.
3. 폴더 안에 `nmd530-codec.js` · `nmd530-counter.js` · `nmd530-bridge.js` 세 파일이 보이는지 확인한다. (설치 스크립트 `nmd530-bridge-install.ps1` 도 함께 있어야 한다.)
   - 압축을 풀었더니 `C:\nmd530-src\nmd530-src\…` 처럼 폴더가 한 겹 더 생겼으면, 안쪽 파일을 모두 `C:\nmd530-src` 바로 아래로 옮긴다.

### 4. 설치 (관리자 PowerShell)
1. 먼저 **미리보기** (아무것도 설치하지 않고 무엇을 할지만 보여 준다):
```powershell
cd C:\nmd530-src
powershell -ExecutionPolicy Bypass -File .\nmd530-bridge-install.ps1 -SourceDir C:\nmd530-src -WhatIf
```
   - 「주소(Endpoint)」 를 물으면 본사가 알려 준 주소를 붙여넣고 Enter. (미리보기에서도 똑같이 묻고, 설치는 하지 않는다. 암호는 미리보기에서 묻지 않는다.)
2. 빨간 오류가 없고 「WhatIf: …」 줄이 이어지면 **진짜 설치**. `-NoStart` 를 꼭 붙인다 (작업을 **등록만 하고 시작하지 않는다** — 5번 시험을 먼저 하기 위해):
```powershell
powershell -ExecutionPolicy Bypass -File .\nmd530-bridge-install.ps1 -SourceDir C:\nmd530-src -NoStart
```
3. 「주소(Endpoint)」 를 물으면 본사가 알려 준 주소를, 「암호(토큰)」 를 물으면 본사가 알려 준 암호를 붙여넣고 Enter. (암호는 화면에 글자가 안 보이는 게 정상이다. 앞뒤 공백은 자동으로 잘린다.)
4. 다른 값은 건드리지 않는다. (기본값: 기기 `NMD530-1` · 검출기 `192.168.0.5` 포트 `8000` — 바꿔야 하면 `-Device` `-DetectorHost` `-DetectorPort` 로 지정.)
5. 설치 위치는 `C:\ProgramData\maytutu\nmd530` (앱 파일 = `app\nmd530-bridge.js`, 설정 = `config.json`, 상태·로그 = `data`), 작업 스케줄러 항목 이름은 `Maytutu-NMD530-Bridge` 이다.
6. 이미 설치돼 있는 PC 에서 다시 실행하면 돌고 있는 작업을 먼저 멈추고 새 설정을 쓴다. **`-NoStart` 를 빼고 다시 실행하면 작업이 바로 시작된다** — 5번 시험 전에는 계속 붙인다. `node` 가 사용자 폴더(`C:\Users\…`) 아래에 있거나 버전이 18 미만이면 스크립트가 멈추고 안내한다 — 안내대로 `C:\Program Files\nodejs` 에 공용 설치한다.

### 5. 시험 (4단계, 순서대로)
설치 직후 작업은 **멈춰 있다** (`-NoStart`). 아래 순서를 지킨다.

1. **보기만 하는 시험** (서버로 안 보냄 · 스풀·상태 파일도 만들지 않고 화면에 출력만 한다):
```powershell
cd C:\ProgramData\maytutu\nmd530\app
node nmd530-bridge.js --dry --config C:\ProgramData\maytutu\nmd530\config.json
```
   - **주의: 시험하는 동안 작업이 켜져 있으면 안 된다.** 검출기는 접속을 1개만 받는 것으로 보고 있어(제조사 확인 전 가정), 작업(수집기)이 돌고 있는 동안 `--dry` 는 접속을 못 하고 반대로 `--dry` 가 접속을 잡고 있으면 작업이 막힌다. 검출기에 접속하는 것은 이 시험 하나뿐이어야 한다. 혹시 작업이 돌고 있으면 먼저 `Stop-ScheduledTask -TaskName Maytutu-NMD530-Bridge`.
   - 몇 초 안에 누적 검출 숫자가 줄줄이 나오면 성공. `Ctrl+C` 로 멈춘다.
   - 아무것도 안 나오거나 오류가 나오면 아래 7번 표.
2. **작업 시작 + 실제 전송 1건**: 1번 시험이 끝나 `--dry` 창이 닫힌 것을 확인하고 작업을 시작한다.
```powershell
Start-ScheduledTask -TaskName Maytutu-NMD530-Bridge
```
   본사 담당자에게 「시험 시작」 연락 → 본사가 시트에서 `수집기시작` 줄이 생기는지 확인한다.
3. **테스트 피스 1회**: 작업자가 금속 테스트 피스를 검출기에 1번 통과시킨다. 전송이 60초 단위 묶음이라 **2분 안에** 웹 화면 「금속검출 실시간현황」(더보기 메뉴) 또는 시트 `금속검출로그` 에 `검출` 줄이 1건 생기면 성공.
   - 2분이 지나도 `검출` 줄이 안 생기면: 검출기 화면의 NG(검출) 숫자가 올랐는지 본다. **올랐으면** 수집기·전송 문제 → 아래 7번의 `bridge.log` 마지막 20줄을 사진으로 보낸다. **안 올랐으면** 검출기가 그 통과를 NG 로 세지 않은 것이다(테스트 모드·감도 등) → 숫자를 올린 방식을 사진·메모로 알려 준다.
   - **이 시험으로 생긴 `검출` 줄은 진짜 검출과 같은 행으로 시트에 남는다. 지우지 않는다.** 대신 시험 시각과 통과시킨 횟수를 현장 메모 또는 CCP 일지 비고에 적어 둔다 (예: 「10/6 14:20 설치 시험 테스트 피스 1회」). 나중에 그 시각의 검출이 시험이었음을 구분하기 위해서다.
4. **전원 껐다 켜기 확인**: DEV-0007 을 «시작 → 전원 → 시스템 종료» 로 **완전히 끄고**, 전원 버튼으로 다시 켠다. **로그인하지 말고** 5분 기다린다. 수집기는 로그인과 무관하게 시작하도록 등록돼 있으나(시스템 계정 · 부팅 뒤 약 1분 지연) 로그인 전에 Wi-Fi 가 붙는지는 PC 마다 다르다 — 이 시험이 그것을 확인한다. 웹 화면의 연결 표시가 녹색 「정상」이 되면 성공. 빨강이면 로그인한 뒤에 「정상」이 되는지 본다: **로그인 뒤에야 정상이 되면** Wi-Fi 가 로그인 전에 붙지 않는 PC 이므로 본사에 알린다(상시 가동 조건을 다시 정한다).

> 주의: 이 시험 중에는 `nmd530-probe.js` 를 같이 실행하지 않는다. 검출기는 접속을 1개만 받는 것으로 보고 있다(가정).

### 6. 라벨프린터와 함께 되는지 확인
1. 설치 뒤 **QR 라벨 1장**을 인쇄한다.
2. **송장 라벨 1장**을 인쇄한다.
3. 둘 다 평소처럼 나오면 끝. 출력이 느려지거나 멈추면 사진을 찍어 본사에 보낸다 (바로 8번 되돌리기를 하지 말고 연락 먼저).

### 7. 문제 해결

막혔을 때 본사에 보낼 것: 아래 한 줄을 PowerShell 에 입력해 나오는 **마지막 20줄을 사진**으로 보낸다.
```powershell
Get-Content C:\ProgramData\maytutu\nmd530\data\bridge.log -Tail 20
```

| 증상 | 확인 | 조치 |
|---|---|---|
| `node` 인식 안 됨 | PowerShell 을 설치 전에 열었음 | 창을 닫고 관리자로 다시 연다. 그래도 안 되면 2번 재설치 |
| 설치 스크립트 실행 거부 | 관리자 창이 아님 | 관리자 권한 PowerShell 로 다시 연다 |
| `--dry` 에 응답 없음 | 검출기 전원·랜선·W610 불 | W610 전원/LED 확인. 검출기는 `192.168.0.5`, 포트 `8000` |
| `--dry` 가 「이미 실행 중」 하고 종료하거나 접속이 안 됨 | 수집기(작업)가 이미 돌고 있어 검출기 접속을 잡고 있음 | `Stop-ScheduledTask -TaskName Maytutu-NMD530-Bridge` 로 멈춘 뒤 `--dry`. **시험이 끝나면 `Start-ScheduledTask -TaskName Maytutu-NMD530-Bridge` 로 반드시 다시 시작** (안 켜면 재부팅 전까지 수집이 멈춘다) |
| 접속이 안 되고 다른 곳에서 쓰는 중 | 검출기 접속 1개 제한(가정) | probe·다른 PC 접속을 모두 끈다 |
| 웹 화면이 빨강 「수집기 응답 없음」 | DEV-0007 전원/Wi-Fi | 전원·Wi-Fi 확인. 3분 안에 복구되지 않으면 본사 연락 |
| 웹 화면이 주황 「통신 끊김」 | 수집기는 정상, 검출기 쪽 문제 | W610 전원·랜선 확인 |
| 서버가 「auth」 거절 | 암호(토큰) 오타 | 4번 설치를 다시 실행해 주소·암호를 다시 입력 (재실행은 돌고 있는 작업을 먼저 멈추고 새 암호로 다시 시작한다 — `-NoStart` 를 붙였으면 `Start-ScheduledTask` 로 시작) |
| 서버가 거른 이벤트 (상태 폴더 `C:\ProgramData\maytutu\nmd530\data` 에 `rejected.jsonl` 이 생김) | 수집기·수신부 버전 불일치 가능 | 파일을 지우지 말고 담당자에게 전달한다 |
| 검출기 화면에 LAN : N/A | 통신은 되는데 N/A 로 표시됨 | 뜻은 제조사 확인 중 ([MFR_INQUIRY ②](MFR_INQUIRY_NMD530.md)). 답이 오기 전까지는 사진만 찍어 둔다 |

### 8. 되돌리기 (필요할 때만)
```powershell
cd C:\nmd530-src
powershell -ExecutionPolicy Bypass -File .\nmd530-bridge-install.ps1 -Remove
```

- 작업을 멈추고(프로세스가 끝날 때까지 최대 약 10초 기다림) 작업 스케줄러 항목과 `app` 폴더를 지운다. 폴더를 못 지우면 「수동 삭제 필요」 로 안내한다.
