# 완제품 코드 전환 가이드 — 5kg 4팩 → 3팩

> 앙호두 호두과자 완제품의 **박스 포장 규격을 4봉/박스 → 3봉/박스로 전환**할 때의 업무 절차입니다.
> 봉지(5kg/봉)는 그대로이고 **박스에 몇 봉을 담느냐(박스당 봉수)만** 바뀝니다.
> 스마트팩토리 재고 화면: `#inventory` → 완제품 탭

---

## 한눈에 보기 (역할별 요약)

| 역할 | 전환 당일 | 이후 상시 |
|---|---|---|
| **관리자** | 앱에서 3팩 코드 등록 + 코드 재분류 실행 (~2분) | 신규 생산 WO를 3팩 코드로 생성 |
| **작업자** | **아무것도 안 함** (봉지·라벨·냉동창고 그대로) | **박스에 3봉씩 포장** (4팩 주문만 4봉) |

> 핵심: 이번 전환은 **장부(시스템)상 코드만 이동**합니다. 창고 봉지를 다시 싸거나 라벨을 새로 붙이지 않습니다.

---

## 1. 관리자 — 전환 당일 (앱에서, 약 2분)

### 1-1. 신규 3팩 완제품 코드 등록
1. 하단 메뉴 → **완제품 품목** 화면으로 이동
2. 우측 하단 **`+`** 버튼 → **신규 완제품 등록**
3. 입력:
   - **품목코드**: 자동 추천값(`FG###`) 그대로 사용
   - **제품명**: 기존과 동일하게(예: `앙호두 호두과자`) — 원하면 `…(3팩)` 표기 추가 가능
   - **봉당 중량**: `5` (kg)
   - **박스당 봉수**: **`3`**  ← 이 값이 4팩과 3팩을 구분하는 핵심
   - 보관: `냉동 -18℃ 이하`
4. 저장

### 1-2. 코드 재분류 실행
1. **완제품 품목** 화면 상단 **`🔀 완제품 코드 재분류 (5kg 4팩→3팩 등)`** 버튼
2. 모달에서:
   - **원 코드**: 기존 4팩 코드 선택
   - **대상 코드**: 방금 만든 3팩 코드 선택
   - **원 코드에 남길 재고(박스)**: `50` (기본값)
3. **`🔎 미리보기`** → 계획 확인
   - 예: `FG002 잔류: 12 LOT · 208봉 ≈ 52.0박스` / `FG003 이관: 30 LOT · 1120봉 ≈ 373.3박스`
   - **소비기한 임박분이 3팩으로 이관**되고, **신선분 50박스가 4팩에 남습니다**(버퍼).
   - 잔류는 LOT 경계로 반올림되어 정확히 50이 아닐 수 있습니다(예: 52박스) — 정상입니다.
4. **`재분류 실행`** → 확인
5. 완료 토스트 확인. 재고 화면(`#inventory` 완제품 탭)에 **4팩·3팩 두 SKU로 분리 표시**되는지 확인

> ⚠️ 원 코드에 재고가 잔류 기준(50박스) 이하이면 "이관할 재고 없음"으로 표시됩니다. 이땐 이관할 것이 없다는 뜻입니다.

### 1-3. 이후 신규 생산
- 새로 만드는 완제품은 **작업지시(WO) 생성 시 3팩 코드**를 선택합니다.
- 그러면 생산·냉동·출하승인 절차는 기존과 똑같고, 재고는 자동으로 3팩으로 적립됩니다.
- 4팩 코드는 잔여 50박스가 소진되면 더 이상 생산하지 않습니다.

---

## 2. 작업자 — 해야 할 일

### 2-1. 전환 당일: **물리 작업 없음**
- 냉동창고의 봉지·QR 라벨·박스를 **그대로 두세요.** 다시 싸거나 라벨을 바꿀 필요가 없습니다.
- 재분류는 관리자가 앱에서 처리합니다.

### 2-2. 이후 출고할 때 (실제로 바뀌는 건 이것뿐)

| 주문 종류 | 박스 포장 | 출고 스캔 |
|---|---|---|
| **3팩 주문** (기본) | 박스당 **3봉** | 3팩 코드 재고에서 봉 QR 스캔 |
| **4팩 주문** (잔여 버퍼) | 박스당 **4봉** | 4팩 코드 재고에서 봉 QR 스캔 |

- 봉지에 붙은 **QR은 기존 그대로 스캔**됩니다(라벨·LOT 번호 안 바뀜).
- 냉동창고 출하 온도 스탬프, 출하기록 등 **나머지 출고 절차는 전과 동일**합니다.
- **정리: 바뀌는 건 "박스에 몇 봉 담느냐" 하나** (3팩이면 3봉).

## 3. 자주 묻는 질문

**Q. 봉지를 다시 포장하나요?**
아니요. 봉지는 그대로입니다. 박스에 담는 봉 개수(4→3)만 달라집니다.

**Q. 봉 라벨(QR)을 새로 붙여야 하나요?**
아니요. 기존 라벨 그대로 스캔됩니다. 시스템 코드만 이동했기 때문입니다.

**Q. 왜 임박분(소비기한 가까운 것)을 3팩으로 옮기나요?**
3팩이 앞으로의 **주력·고회전 라인**이라 오래된 재고부터 자연히 먼저 나갑니다(FEFO). 4팩 버퍼(50박스)는 신선분을 남겨, 4팩 주문이 뜸해도 상하지 않게 합니다.

**Q. 50박스를 정확히 안 남기고 52박스가 남았어요.**
정상입니다. 봉을 쪼개 재라벨하는 일을 피하려고 **LOT 단위로 반올림**합니다. 미리보기에서 실제 수량을 확인하고 실행하세요.

**Q. 잘못 실행했어요. 되돌릴 수 있나요?**
같은 방식으로 **대상↔원 코드를 반대로** 재분류하면 되돌릴 수 있습니다(봉 QR·LOT은 그대로라 안전). 다만 실행 전 미리보기로 반드시 확인하세요.

**Q. 재분류 기록은 어디에 남나요?**
`재분류이력` 시트에 자동 기록됩니다(원코드→대상코드·LOT·봉수·실행자·시각). HACCP 추적을 위해 삭제하지 마세요.

---

## 4. 권한 / 안전장치 (요약)

- 재분류는 **관리자 전용**입니다(작업자·뷰어 화면엔 버튼이 없음).
- 실행 중 재고 상태가 바뀐 LOT은 자동으로 건너뜁니다(동시성 방어).
- 봉 QR·LOT ID·개별 ID는 절대 바뀌지 않습니다 → 추적성 100% 보존.
- 이력은 append-only(덧붙이기만) 기록되어 위·변조 방지 원칙과 일치합니다.
