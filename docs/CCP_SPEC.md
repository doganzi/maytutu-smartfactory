## 1. 목적 / 범위 / 비범위

- **목적**: HACCP 2개 중요관리점(CCP)의 종이 모니터링 양식을 앱 내 구조화 기록으로 전환하고, 기존 기록을 새 양식으로 이관한다.
- **범위(In)**: ① 신규 시트 2개 ② 입력 UI 2종 ③ HACCP 통합뷰·부적합 알림 ④ 종이형 PDF 기록부 출력 ⑤ 기존 금속검출 기록 변환 ⑥ 동결온도 CCP의 Smart Life(데이터로거) **연결 슬롯**(값 주입은 프로젝트2).
- **비범위(Out)**: Smart Life 실연동 구현(메일수집/Tuya API)은 **프로젝트2**에서 별도 진행. 전자결재 워크플로(승인 권한 전결규정)는 현행 `작성자/승인자` 텍스트 기입 수준 유지. 타 CCP(가열 등)는 본 SPEC 비범위.

## 2. 분석 — 확정된 양식 구조

### CCP-1 동결공정 온도 (모니터링일지·동결공정)
- **위해요소**: 냉동 불충분 → 미생물 증식
- **한계기준**: 냉동고 **−18℃ 이하** · **최소 냉동 12시간 이상**
- **주기**: ① 제품 투입 시 ② 최소냉동시간(12h) 완료 시
- **기록 항목**:
  - 투입: 날짜 · 품목명 · 투입시간 · 냉동고 온도(℃)
  - 종료: 날짜 · 냉동 종료시각 · 냉동고 온도(℃) · **제품 온도(℃)** · 제품상태(적합 ○ / 부적합 ×)
- **판정**: 제품온도 ≤ −18℃ AND 경과 ≥ 12h → 적합
- **데이터로거**: "확인 불가 시간대의 냉동고 온도는 데이터로거 자료로 확인" → **Smart Life 센서가 데이터로거**
- **개선조치**(부적합 시): 정상 냉동고로 이동 → 제품온도 측정 → −18℃ 초과 시 부적합품 처리(선별·폐기) / 추가 냉동 후 재확인 / 미생물 검사(적합=재밀봉, 부적합=폐기) / HACCP팀장 보고 후 기록

### CCP-2 금속검출 (금속검출기 CCP 모니터링 기록부)
- **위해요소**: 금속성 이물질 잔존(SUS·Fe 나사·칼날·톱날·못)
- **대상/한계기준**: 전제품 · **Fe 2.5mm / SUS 4.0mm 이상 100% 검출**
- **빈도**: 작업시작 전 · 작업 중 **2시간마다** · 작업종료 후
- **격자(감시시각 1행당)** — 각 칸 `검출 / 불검출`:
  | 항목 | 칸 | 정상(기본) |
  |---|---|---|
  | 시편 철(Fe) | 좌·중·우 (3) | **검출** (검출기 정상작동) |
  | 시편 써스(SUS) | 좌·중·우 (3) | **검출** |
  | 제품 통과 | 1 | **불검출** (제품에 금속 없음) |
  | 제품+시편(Fe) | 상단 좌중우 + 하단 좌중우 (6) | **검출** |
  | 제품+시편(SUS) | 상단 좌중우 + 하단 좌중우 (6) | **검출** |
  - → 행당 19칸. "정상" 상태가 명확하므로 **기본값=정상**, 작업자는 예외(이탈)만 탭.
- **하단 요약**: 품명 · 통과량 · 검출량 · 특이사항
- **개선조치**: 감도미흡(2~3회 반복 통과로 감도조정) / 이물발견(재통과 확인·제거, 오염품 폐기, 재검사 후 재사용) / 기계고장(고장 2h 전 생산품 별도보관, 수리 후 재검사)

## 4. UI / 입력 흐름

### CCP-1 동결온도 — WO `store`(냉동) 단계 연동
- WO 실행 중 `store` 단계(냉동시작)에서 **투입 기록 자동 생성**: 투입_날짜/시각=냉동시작, 투입_냉동고온도=Smart Life(없으면 수동·온도계 사진 유지).
- **출하 승인(12h↑) 화면**에서 **종료 입력**: 종료_냉동고온도·**제품온도(필수)** → 판정 자동(≤−18 & ≥12h).
- 판정 `부적합` 시 출하 차단 + 이탈/개선조치 입력 강제(기존 출하승인 게이트와 연결).
- 현 `store` 단계의 "냉동고 온도계 사진/보관시작시간"은 동결온도 CCP로 흡수(중복 제거).

### CCP-2 금속검출 — 시간행 격자(종이 100%)
- 헤더: 날짜·제품명·점검자(자동) + 한계기준/방법/개선조치 안내(접이식).
- 행 추가: `작업시작전`(1) · `+2시간`(반복) · `작업종료`(1). 각 행 = 19칸 토글, **기본=정상**, 예외만 탭하면 색·이탈 표시.
- 하단: 통과량·검출량·특이사항. 이탈 1건↑ → 판정종합 부적합 + 개선조치 입력 유도.
- 기존 7단계 위저드(`inspect`/CCP) 입력 경로는 본 격자 화면으로 대체.

## 5. 자료 관리

- **보존**: Sheets 영구 + LOT/WO 추적성. 출하완료·승인 행은 삭제 보호(기존 HACCP 보존 규칙 준수).

## 7. Smart Life 연결점 (프로젝트2 인터페이스)

- `CCP_동결온도.투입_냉동고온도 / 종료_냉동고온도 / 데이터로거참조`가 주입 지점.
- 인터페이스 계약(프로젝트2에서 채움): `{ deviceId, ts, tempC, source:"smartlife" }` 시계열 → 투입/종료 시각의 최근값 매칭 + 구간(−18℃ 유지) 증빙 요약.
- 후보 방법(프로젝트2에서 비교 결정): ① Gmail(연결됨) Smart Life 알림메일 파싱 → 시트 ② Tuya Cloud API 폴링(cron). 본 SPEC은 슬롯만 마련.

## 9. 종단 검증 (end-to-end, 라이브)

1. `CCP_금속검출` 신규 1건 입력(이탈 포함) → 시트 저장·HACCP뷰 표시·부적합 강조 확인
2. WO 냉동시작 → `CCP_동결온도` 투입 자동생성 → 12h 후 종료입력 → 판정 자동·출하게이트 연동 확인
3. 마이그레이션 드라이런 리포트 → 변환 → 변환본이 신규 입력과 동일 렌더 확인
4. PDF 기록부 출력 = 종이 양식과 항목·결재란 일치 확인
5. 정합성 검증(`data-audit`) 신규 2규칙 Pass
> 데이터 확인은 로그인된 노트북 브라우저(라이브 앱·시트)로 수행. PR→프리뷰→검증 후 main.

## 11. 가정 / 미해결

- 7단계 `stepData` JSON의 정확한 키는 **구현 시 라이브 기록 표본으로 확정**(매핑 미세조정).
- 결재(작성/승인) = 텍스트 기입 유지(전자서명·전결규정 자동화는 추후).
- Smart Life 연동 방법은 프로젝트2에서 ①메일 ②Tuya API 비교 후 결정.
- 동결 12h 경과 판정의 기준시각 = WO `store` 냉동시작([11]). 다배치 동시냉동 시 배치별 row 분리.

## 12. 센서 온도값 선정 규칙 · 이탈 사유 기록 (2026-07-27)

### 12-1. 배경 — 문 개방 순간값이 창고 보관온도로 기재되던 문제

`동결온도로그`(Tuya 센서, 10분 자동기록)에서 **기준시각에 가장 가까운 1건**을 그대로 일지에 적으면,
**제품 투입 = 냉동창고 문을 여는 작업**이라 문 개방 순간의 상승값(관측 사례: `-13.3℃`)이 잡힌다.
실제로는 −18℃ 이하를 유지한 창고인데도 작업지시서 PDF의 「모니터링일지(동결공정)」에는
한계기준 이탈로 남고, 개선조치 근거가 없는 이탈 기록이 누적된다.

### 12-2. 선정 규칙 (`pickFreezerTemp`, `index.html`)

| 순서 | 규칙 |
|---|---|
| ① | 대상 = 기기명에 `냉동창고` 포함 · 기준시각 앞 60분 ~ 뒤 40분 창(window) 내 **실측값**(결측 제외) |
| ② | **사유가 기록된 순간 이탈은 후보에서 제외** — 성애 제거(제상)·문 열림 등 `transient` 프리셋 사유에 한함. 제외 내역(시각·온도·사유)은 PDF 각주로 **반드시 함께 표기**(삭제·은폐 아님) |
| ③ | 투입 온도 = **기준시각 직전 최근값**(문 개방 전 창고 상태). 직전값이 없으면 직후값 |
| ④ | 출하(종료) 온도 = 최근 6시간 내 최근값(같은 ②규칙 적용). 6시간 내 기록이 없으면 전 구간 최근값 + 경과시간 경고 |
| ⑤ | ②~④ 후에도 −18℃를 초과하면 **그 값을 그대로 기재**하고 `dev` 표시(붉게·굵게) + 「이탈내용」 칸에 `[자동]` 문구 자동 기재. **사유 없는 이탈은 절대 대체하지 않는다** |
| ⑥ | 직접입력(프리셋 외) 사유는 `transient`로 보지 않는다 — 판단 근거가 없으므로 대표값에서 제외하지 않음(보수적) |

수기 입력값(legacy `stepData.freezeTemp`)이 있으면 그 값이 항상 우선한다(센서 보정 대상 아님).

### 12-3. 이탈·결측 사유 (`동결온도로그` G~I열)

| 열 | 이름 | 기재 |
|---|---|---|
| G | `이탈사유` | 성애 제거(제상) / 문 열림(투입·반출·점검) / 설비 고장·수리 / 정전 / 센서·통신 오류 / 직접입력 |
| H | `사유기록자` | 로그인 계정 ID (자동) |
| I | `사유기록시각` | 저장 시각 KST (자동) |

- 입력 위치: 앱 **동결온도 모니터링**(`#temp-log`) 로그 표의 **판정 옆 `사유` 칸** → `＋사유`.
- 성애 제거 1회는 기록 여러 건(10분 간격)에 걸치므로 **연속 이탈·결측 구간 일괄 적용**을 지원한다.
- 화면 상단에 **사유 미기재 건수 배너**, 「동결·냉장 온도 점검 기록부」 PDF에는 `사유` 열과 미기재 건수를 표기한다(빈칸은 기록 완료로 오독되므로 `미기재`로 명시).
- Apps Script(`tuya_temp_logger.gs`)는 **A~F열만 적재**하므로 사유 칸을 덮어쓰지 않는다.
