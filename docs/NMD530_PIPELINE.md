# NMD-530 금속검출기 → 스마트팩토리 자동 기록 파이프라인 (계약서)

> 이 문서가 수집기·시트 수신부·웹 화면 세 갈래의 **공유 계약**이다. 세 곳 중 하나를 바꾸면 이 문서를 먼저 고친다.
> 프로토콜(프레임·명령)은 [`../bridge/README.md`](../bridge/README.md) 와 `bridge/nmd530-codec.js` 가 정본이다.
> 이 저장소는 **public** 이다 — 토큰·웹앱 주소(`/exec` URL)·시트 ID 를 어떤 파일에도 쓰지 않는다.

## 1. 목적과 경계

| | |
|---|---|
| 하는 일 | 검출기가 센 **누적 검출(리젝트) 수**를 3초마다 읽어, **증가분·시각·통신 끊김·카운터 리셋**을 구글 시트에 자동 적재하고 웹 화면에 보인다. |
| 하지 않는 일 | ① 시편(Fe/SUS) 감도 확인 대체 — 작업자의 물리 행위라 CCP-1P 수기 일지와 **병행**한다. ② 검출기 설정 변경·제품 변경(`0x60`)·대량 이력(`0x3A`) — **보내지 않는다**. ③ 생산수량 — 실측상 항상 0 이라 쓰지 않는다. ④ CCP 일지 칸 자동 채우기 — 참고 줄만 보인다. |
| 근거 | 자동 기록은 장비 실측이라 날조가 아니다. 단 **측정하지 못한 시간을 «이상 없음» 으로 보이면 날조**다 → 통신 끊김·수집기 정지·카운터 리셋은 숨기지 않고 «모니터링 공백» 으로 따로 센다(동결온도 화면이 결측을 적합으로 위장한 사고의 교훈). |

## 3. 계수 규칙 (카운터 엔진 — `bridge/nmd530-counter.js`, 순수 함수)

입력: 유효한 0x35 응답 1건(`{t(ms), total, product, ch1, ch2, lv1, lv2, flags[], prod}`) 또는 «응답 없음» 시계 눈금.
출력: 이벤트 배열(아래 §4). 상태: `{lastTotal, lastValidAt, down, downSince, seq}`.

| 상황 | 판정 | 이벤트 |
|---|---|---|
| 첫 관측(저장된 기준 없음) | 기준만 잡는다. 증가분을 지어내지 않는다 | `COLLECTOR_START` (total) |
| `total > lastTotal` 이고 직전 유효 관측과 간격 ≤ `downAfterMs` | 그 사이 `n = total − lastTotal` 건 검출. 3초 폴링 사이 연속 검출은 한 번에 +N 으로 합쳐진다 | `DETECT` (n, prev, from=직전 관측 시각) |
| `total > lastTotal` 이고 간격 > `downAfterMs`(끊김·재시작 사이) | 검출은 있었으나 **시각을 알 수 없다** | `GAP` (n, prev, from) |
| `total == lastTotal` | 이벤트 없음 | — |
| `total < lastTotal` | 카운터 리셋(전원 사이클 등). **증가분을 만들지 않는다**(리셋 전 구간은 알 수 없음). 새 값이 기준 | `RESET` (prev, total) |
| 유효 응답이 `downAfterMs`(기본 30초) 넘게 없음 | 통신 끊김 선언(연결 파기·재접속 시도). **끊김이 이어지는 동안 `downAfterMs` 마다 소켓을 다시 파기·재접속한다**(재접속한 소켓이 TCP 만 붙고 응답이 없어도 영구히 머물지 않는다) | `LINK_DOWN` (t = 마지막 유효 관측 이후 선언 시각, from=마지막 유효 시각) |
| 끊긴 뒤 첫 유효 응답 | 복구. 끊긴 동안의 증가분이 있으면 이어서 `GAP` | `LINK_UP` (downSec) |
| 수집기 프로세스 시작 | 직전 종료 시각(state.json `lastValidAt`)을 `from` 으로 | `COLLECTOR_START` (from, total) |

- **시계 역행·비정상 값**: PC 시계가 마지막 유효 관측보다 과거로 가면 기준 시각을 현재로 당겨 끊김 판정이 멎지 않게 하고, 간격이 음수인 증가는 `GAP`(시각 미상)으로 센다. 그 경우에도 `LINK_UP.downSec` 은 0 이상이고(음수 금지), `from` 이 이벤트 시각 `t` 보다 미래이면 `null` 로 적는다(거꾸로 된 구간을 만들지 않는다). `total` 이 유한한 0 이상의 정수가 아니면 **유효 응답이 아니다**(기준선을 건드리지 않는다).
- **비정상 종료 복구**: 이벤트는 스풀에 먼저 쓰고 상태를 나중에 저장하므로, 그 사이에 죽으면 상태가 스풀보다 뒤처질 수 있다. 시작 시 스풀 끝 이벤트의 `total`·`seq` 가 상태보다 앞서 있으면 상태를 스풀 기준으로 끌어올린다(같은 증가분이 `GAP` 으로 한 번 더 세어지지 않게).
- **늦게 몰려 온 응답**(Wi-Fi 구간 끊김 뒤 지연 1.5~1.8초): 응답이 어느 요청의 것인지 가리지 않고 **유효 프레임은 전부 같은 규칙으로 처리**한다. 누적값은 단조 증가이므로 몰려 와도 해가 없다. 동시에 미응답 요청은 최대 3개까지만 쌓는다.
- **시각은 수집 PC 시계**(KST `+09:00` 명시). 검출기 시계는 약 +16분 53초 빠르다(2026-10-04 실측, 수집 PC 시계 기준 · 제조사 문의 중) — 쓰지 않는다. 서버(Apps Script)는 별도로 수신 시각을 적어 PC 시계 어긋남이 보이게 한다.
- `UInt16` 상한(65535) 되돌이는 리셋과 구분되지 않는다 — 실사용상 도달하지 않으므로 별도 처리하지 않는다(문서화만).
- 화면의 «기간 검출 합계» = 기간 안 `DETECT.n` 합 + `GAP.n` 합. 둘은 **따로 표시**한다(시각 확정 N건 + 구간 내 N건).

## 4. 이벤트 (수집기 → 수신부)

```jsonc
{
  "id":   "NMD530-1|20261005T102030K|0007",   // `${device}|${bootId}|${seq}` — 재전송해도 같은 값(멱등 키), ≤ 80자
  "t":    "2026-10-05T10:20:33+09:00",          // 관측 시각(수집 PC), 오프셋 +09:00 고정
  "kind": "DETECT",                             // DETECT | GAP | RESET | LINK_DOWN | LINK_UP | COLLECTOR_START
  "n":    2,            // DETECT·GAP: 증가분(≥1). 그 외 null
  "total": 53,          // 이벤트 직후 누적 검출 카운터. LINK_DOWN 은 null
  "prev":  51,          // DETECT·GAP·RESET: 이전 값. 그 외 null
  "from":  "2026-10-05T10:20:30+09:00",         // DETECT·GAP·RESET·LINK_DOWN·COLLECTOR_START: 구간 시작(직전 유효 관측). 없으면 null
  "product": 1, "ch1": 100, "ch2": 0,           // 마지막 유효 응답의 제품번호·채널 신호(없으면 null)
  "flags": ["testMode"],                        // 상태 비트: outError | balError | testMode | dualFreq (bit0·bit5 는 예약이라 내보내지 않음)
  "downSec": null       // LINK_UP: 끊김 지속 초. 그 외 null
}
```

## 5. 전송 규약 (수집기 → 웹앱)

`POST <ENDPOINT>` · `Content-Type: application/json` · 본문:

```jsonc
{
  "v": 1,
  "token": "<공유 비밀>",          // 서버 스크립트 속성 NMD530_TOKEN 과 일치해야 함
  "device": "NMD530-1",
  "host": "<수집 PC 이름>",        // os.hostname()
  "collector": "nmd530-bridge/1.0.0",
  "sentAt": "2026-10-05T10:21:00+09:00",
  "events": [ /* §4, 0~50건 */ ],
  "status": {                      // heartbeat — 매 전송에 최신 1건(null 가능)
    "link": "UP",                  // UP | DOWN
    "total": 53, "product": 1, "flags": [], "lastValidAt": "…+09:00",
    "downSince": null, "spool": 0, "bootAt": "…+09:00"
  }
}
```

**응답 해석 (⚠ 실측 반영 — 메모리 `apps-script-webapp-echo-from-vercel`)**
1. POST 는 리다이렉트를 따라가지 않는다(`redirect manual` 상당). Apps Script 는 `doPost` 가 **끝난 뒤** 302 를 준다.
2. 302 의 `Location`(googleusercontent echo)을 **GET 한 번만** 읽는다(두 번째부터는 읽히지 않는다). 본문이 JSON `{"ok":true,…}` 이면 **확인됨**.
3. 확인되지 않으면(HTML·타임아웃·연결 끊김) **스풀에 그대로 두고 같은 이벤트ID 로 재전송**한다 — 서버가 중복을 걸러 주므로 안전하다(at-least-once + 멱등 = 정확히 한 번의 효과).
4. 확인된 이벤트만 스풀에서 지운다. 재전송 간격은 5초에서 시작해 두 배씩 늘려 5분 상한.
5. `ok:true` 여도 `badIdx` 가 비어 있지 않으면 그 위치의 이벤트는 **재전송하지 않는다**(고쳐지지 않는다) — 스풀에서 빼 `rejected.jsonl`(죽은 편지함)에 보관하고 로그에 크게 남긴다. 나머지만 확인된 것으로 지운다. 조용히 사라지는 이벤트는 없다.
6. 200 이 직접 오는 경우(시험용 가짜 서버·프록시)도 같은 JSON 확인 규칙을 적용한다.

수신부 응답: `{"ok":true,"v":1,"saved":N,"dup":M,"bad":K,"badIdx":[0,3]}` — `badIdx` 는 **이번 요청 `events` 배열에서 형식 오류로 걸러진 항목의 0 기반 위치**(`bad` 와 같은 개수, 없으면 빈 배열) 또는 `{"ok":false,"error":"auth|bad_request|server"}`. 오류 응답에 스택·내부 값을 싣지 않는다.

## 6. 시트 스키마 (수신부가 없으면 만든다 · 헤더 1줄 · `SHEET_ID` 스크립트 속성)

### «금속검출로그» — 이벤트 1건 = 1행 (A~O: 수신부 전용)
| 열 | 헤더 | 값 |
|---|---|---|
| A | 기록시각(KST) | `yyyy-MM-dd HH:mm:ss` — `t` 를 KST 로. **텍스트 서식 `@`** (자동 날짜 변환 금지) |
| B | 구분 | 검출 · 미관측구간 · 리셋 · 통신끊김 · 통신복구 · 수집기시작 (kind → 한글) |
| C | 증가분 | 숫자 또는 빈칸 |
| D | 누적검출 | 숫자 또는 빈칸 |
| E | 이전값 | 숫자 또는 빈칸 |
| F | 구간시작 | `from` 을 같은 서식으로. 없으면 빈칸 (`@`) |
| G | 제품번호 | 숫자 또는 빈칸 |
| H | 설비상태 | flags 한글 `·` 연결: `Out error`, `Bal error`, `테스트 모드`, `듀얼 주파수`. 정상=빈칸 |
| I | Ch1신호 | 숫자 또는 빈칸 |
| J | Ch2신호 | 숫자 또는 빈칸 |
| K | 끊김(초) | `downSec` 또는 빈칸 |
| L | 기기 | device |
| M | 수집PC | host |
| N | 서버수신시각 | Apps Script 시계 KST (PC 시계 어긋남 확인용, `@`) |
| O | 이벤트ID | 멱등 키 |
| P~ | (예약) | 앱이 사람 입력(사유 등)을 쓸 자리 — 수신부는 건드리지 않는다 |

텍스트 서식 `@` 를 먼저 거는 열 = **A·F·L·M·N·O** (시각·기기 이름·이벤트ID 가 날짜·숫자로 자동 변환되지 않게). C~E·G·I·J·K 는 숫자 열.

### «금속검출상태» — 기기당 1행 (A~M 수신부 전용 · 기기 기준 upsert)
A 기기 · B 서버수신시각(KST) · C 수집PC시각 · D 통신(UP/DOWN) · E 누적검출 · F 마지막유효관측 · G 제품번호 · H 설비상태 · I 대기큐 · J 수집PC · K 수집기버전 · L 끊김시작 · M 가동시작
텍스트 서식 `@` 열 = **A·B·C·D·F·J·K·L·M** (E·G·I 는 숫자, H 설비상태는 서식 없는 문자열).

## 7. 수신부 규칙 (`apps-script/nmd530_receiver.gs`)
- 스크립트 속성: `NMD530_TOKEN`(필수) · `SHEET_ID`(필수, Tuya 로거와 같은 값) · `NMD530_DEVICES`(선택, 콤마 구분 허용 기기 목록. 비면 검사 안 함).
- `doPost(e)` 순서: 본문 파싱 → `v==1` → **토큰 비교(틀리면 어떤 정보도 주지 않고 `auth`)** → 이벤트 ≤ 200 → `LockService.getScriptLock().waitLock(20000)` → 시트 확보(없으면 헤더와 함께 생성) → **끝에서 5000행의 O열(이벤트ID)** 을 프로토타입 없는 집합(`Object.create(null)`)으로 → 새 이벤트만 한 번에 `setValues` (A·F·L·M·N·O 열에 `@` 서식 먼저) → 상태 행 upsert → `SpreadsheetApp.flush()`(쓴 값을 확정해 다음 요청이 옛 값을 읽지 않게) → 잠금 해제 → 응답.
- 이벤트 하나가 형식 오류면 그것만 `bad` 로 세고 나머지는 적재한다(전체 거부 금지). **걸러진 위치는 응답 `badIdx` 에 싣고 `Logger.log` 에 남긴다**(§5 — 수집기가 죽은 편지함으로 옮긴다).
- 검증 강화: 시각은 정규식 통과 뒤 **월·일·시·분·초가 실제로 존재하는 값**이어야 한다(`2026-02-30`·`24:00:00` 은 `bad`, 다른 날로 조용히 바뀌지 않는다). `n`·`downSec`·`total`·`prev`·`product`·`ch1`·`ch2` 는 **유한한 0 이상의 정수**여야 하고(`n` 은 DETECT·GAP 에서 ≥1), 아니면 `bad`.
- 상태 upsert 는 **수집PC시각(`C`, 요청 `sentAt`)이 기존 행보다 과거면 덮어쓰지 않는다**(락 순서로 늦게 도착한 옛 요청이 신선한 상태를 되돌리지 못하게). 단 **10분을 넘게 과거**이면 늦게 온 요청이 아니라 «수집 PC 시계가 바로잡힌 것» 으로 보고 덮어쓴다(미래로 어긋난 시각이 상태 행을 영구히 얼리지 않게). 텍스트 서식 `@` 는 상태 시트의 문자열 열 전부(통신 `D` 포함)에 먼저 건다.
- `doGet` = `{service:"nmd530_receiver",ok:true}` (건강 확인용. 데이터 없음).
- 보내는 쪽이 보낼 수 있는 `kind` 외의 값·`id` 80자 초과·시각 파싱 불가는 `bad`.
- 일반 안전: 문자열은 시트에 **값으로만** 쓴다(수식 주입 방지 — `=`,`+`,`-`,`@` 로 시작하면 앞에 `'` 를 붙이지 않고 `setValues` 가 텍스트 서식 `@` 열이므로 안전. C~E·G·I·J·K 는 숫자 검증 통과분만).
- 배포: «웹 앱 · 실행: 나 · 액세스: 모든 사용자» (익명 — 토큰이 유일한 방어). 배포·속성 입력은 **사용자 구글 로그인이 필요**해 사람이 한다(`apps-script/SETUP_NMD530.md`). 배포 뒤 `nmd530_selfTest` 를 한 번 실행해 시트 생성·적재·중복 방지를 확인한다(같은 이벤트ID 2건을 두 번 보내 1차 saved:2 · 2차 saved:0 dup:2 가 나오면 합격. 시트에 `SELFTEST|…` 행 2건이 남는다 — **합격 확인 뒤 지운다**, 안 지우면 «수집기시작» 으로 화면에 보인다).

## 8. 수집기 규약 (`bridge/nmd530-bridge.js`)
- **보내는 명령은 허용 목록 `{0x33, 0x2A}` 뿐.** 송신 함수가 그 밖의 값이면 예외. `0x60`·`0x3A` 는 코드·테스트 어디서도 와이어에 나가지 않아야 한다.
- 접속은 **한 번에 하나**. 같은 상태 폴더에 `bridge.lock`(PID) — 살아 있는 다른 수집기가 있으면 즉시 종료(중복 적재 방지 + 검출기가 접속 1개만 받는다는 **가정** — 제조사 문의 ④ 로 확인 중). 잠금 획득과 PID 기록 사이의 경쟁은 알려진 한계로 남긴다(작업 스케줄러가 `IgnoreNew` 로 중복 실행을 막는다).
- 설정 우선순위: 명령행 플래그 > 환경변수(`NMD530_ENDPOINT`, `NMD530_TOKEN`) > `--config` JSON > 기본값. **토큰은 플래그로 받지 않는다**(프로세스 목록 노출).
  기본값: `host 192.168.0.5` · `port 8000` · `device NMD530-1` · `intervalMs 3000` · `heartbeatMs 60000` · `downAfterMs 30000` · `stateDir <스크립트 폴더>/nmd530-data`(작업 폴더 상대가 아니다 — 어디서 띄워도 같은 잠금·같은 스풀). `device` 는 1~40자(이벤트ID ≤ 80자 보장).
- 플래그: `--config <json>` `--host` `--port` `--endpoint` `--device` `--interval` `--heartbeat` `--down-after` `--state-dir` `--dry`(전송 대신 출력 — **스풀·상태 파일을 만들지 않는다**) `--selftest` `--version`.
- 상태 폴더: `state.json`(`lastTotal`·`lastValidAt`·`seq`, 임시파일→rename 으로 원자 저장) · `spool.jsonl`(이벤트 쓰기 선행 기록 — 시작 시 마지막 줄이 줄바꿈 없이 잘려 있으면 줄바꿈을 먼저 붙여 복구) · `rejected.jsonl`(§5-5 서버가 거른 이벤트 보관) · `bridge.log`(1 MB × 3 회전) · `bridge.lock`.
- 설정 파일 해석 오류 메시지에 파일 내용 조각을 싣지 않는다(토큰 노출 방지). 상태 파일이 깨졌으면 `state.json.corrupt-<시각>` 으로 옮겨 보존하고 로그에 크게 남긴 뒤 «첫 관측» 으로 시작한다.
- 재접속: 지수 백오프 1→2→4…30초 상한. **접속이 붙은 것만으로는 리셋하지 않고, 첫 유효 응답을 받았을 때** 처음으로 되돌린다(TCP 만 붙고 말이 없는 장비에 1초 간격으로 매달리지 않게). 접속 중 `intervalMs` 마다 `0x33`. 미응답 요청은 최대 3개 — **깨진·낯선 프레임도 무언가에 대한 답이므로 미응답 수에서 뺀다**(안 빼면 미응답이 쌓여 폴링이 멎는다). 수신부가 `bad` 로 센 이벤트 중 위치를 특정하지 못한 것이 있으면 로그에 경고한다.
- 종료(SIGINT/SIGTERM): 상태 저장 후 소켓·타이머 정리. 비정상 종료(전원 차단)는 다음 시작의 `COLLECTOR_START.from` 으로 공백이 드러난다.
- 자원: 상주 메모리 50 MB 이하를 목표(같은 PC 가 QR·송장 라벨프린터를 구동한다). 폴링·전송 외 작업 없음.
- Windows: `bridge/windows/nmd530-bridge-install.ps1` — 작업 스케줄러 «시작 시» 트리거, 실패 시 1분 간격으로 최대 999회 재시작(약 16시간 — 그 뒤에도 안 살아나면 웹 화면의 빨강 «수집기 응답 없음» 으로 드러난다), 배터리에서도 시작·유지, 중복 실행 무시, 설정·토큰은 `C:\ProgramData\maytutu\nmd530\`(Users 읽기 제거). 제거 `-Remove`. Node.js 미설치(또는 사용자 폴더 안 경로)면 안내만 출력하고 중단. `-Endpoint` 를 안 주면 묻는다(비대화형이면 중단). `-NoStart` 로 등록만 하고 시작은 시험 뒤에 한다. 이미 설치돼 있으면 **실행 중인 작업을 먼저 멈추고** 설정을 쓴 뒤 다시 시작한다. 토큰은 앞뒤 공백을 잘라 저장한다.

## 9. 웹 화면 규칙 (`index.html` · `Screens['metal-live']`)
- 데이터: `SheetsAPI.getAll('금속검출로그', false)` · `getAll('금속검출상태', false)` — **읽기 전용**(쓰기 호출 없음).
  - 탭이 아직 없으면(Sheets 응답 400) «수집기 가동 전» 빈 상태 카드(오류 아님).
  - 그 밖의 읽기 실패(권한·네트워크·5xx)는 **«시트를 읽지 못했습니다» 카드 + 다시 시도 버튼** — «기록 0건·공백 0분» 으로 보여 안전하다고 오해하게 하지 않는다. CCP-1P 참고 줄도 줄을 숨기지 않고 «읽지 못함» 경고를 보인다(시트가 정말 비었을 때만 숨김).
- 연결 판정(상태 행의 서버수신시각 `B` 기준, `now` 주입 가능한 순수 함수). 건수 칸(C~E·G·I·J·K)은 **0 이상의 정수만** 숫자로 읽고 빈칸·공백·음수·소수·글자는 «읽지 못함» 으로 센다(0 으로 위장하지 않는다):
  - `B` 가 이 기기 시계보다 2분 넘게 미래 → **시계 불일치** (주황) — 경과 시간을 믿을 수 없으므로 «정상» 으로 위장하지 않는다.
  - `B` 가 3분 이내(경계 포함) & 통신 `UP` → **정상** (녹색)
  - `B` 가 3분 이내 & 통신 `DOWN` → **검출기 통신 끊김 — 수집기는 동작 중** (주황)
  - `B` 가 3분 초과(또는 시각 불명) → **수집기 응답 없음 — DEV-0007 전원·네트워크 확인** (빨강) · 마지막 확인 시각 표시
  - 상태 행 없음 → **가동 전** (회색)
  - (30초 틱 전용) 상태 탭을 새로 읽지 못함 → **상태 시트를 새로 읽지 못함 — 연결을 판단할 수 없음** (주황, 키 `unread`). 옛 값을 «정상» 으로 두지 않는다.
  - 시계 불일치·가동 전·읽지 못함처럼 **판단 불가**인 연결 상태에서는 «지금 진행 중인 공백» 을 계산할 수 없으므로, ⑤ 공백 카드(와 CCP-1P 참고 줄)가 «공백 0분» 을 초록으로 보이지 않고 «계산하지 못했습니다» 경고를 붙인다.
- 기간 필터: 오늘 / 7일 / 30일 / 전체 (동결온도 화면과 같은 칩). 기본 «오늘». 상한은 두지 않는다(미래 시각 행도 버리지 않는다).
- 카드: ① 연결 ② 기간 검출 합계(시각 확정 N + 구간 내 N 따로) ③ 마지막 검출 시각·경과 ④ 설비 상태(Out error·Bal error·테스트 모드 — 상태 행 H) ⑤ **모니터링 공백** ⑥ 리셋 감지 횟수(있으면 «이력 화면 NG 열과 대조» 안내).
  - ⑤ 는 **구간의 합집합** 분 단위(같은 시간을 두 사건이 가리켜도 한 번만 센다, 1초라도 있으면 최소 1분): 통신복구 `[t−끊김초, t]` · 수집기시작 `[from, t]` · **지금 진행 중인 구간** — 통신 끊김이면 `[끊김 시작, 지금]`, 수집기 무응답이면 `[마지막 수신, 지금]`(그 전부터 끊겨 있었으면 `[끊김 시작, 마지막 수신]` 포함). 진행 중이면 «지금도 공백 진행 중» 을 따로 보인다.
  - 읽을 수 없는 행은 합계에서 조용히 빠지지 않는다: 시각(A)을 못 읽은 행(skipped) · 증가분 숫자를 못 읽은 검출 행(unreadable) · 끊김 시간(K)을 못 읽은 통신복구 행(unreadGap)의 건수를 경고 카드로 알린다(0 건·0 분으로 세지 않는다). 끊김 시작(L)이 비어 있으면 마지막 유효 관측(F)부터 끊긴 것으로 센다.
  - ① 연결·⑤ 공백 카드는 시간이 흐르는 만큼 달라지므로 **30초마다 다시 그리되, 이때 상태 탭(기기당 1행)만 새로 읽는다**(로그 탭은 다시 읽지 않는다 — 안 읽으면 화면을 열어 둔 채 3분이 지나는 순간 수집기가 멀쩡해도 «응답 없음» 으로 바뀐다). 이 읽기는 앱의 화면 추적(LiveSync)에 끼어들지 않는다. 읽는 중이면 다음 틱은 겹쳐 읽지 않고, 읽는 사이 화면이 다시 그려졌거나 떠났으면 그 틱의 결과는 버린다. 화면을 벗어나 카드가 없어지면 타이머가 스스로 멈춘다. 읽는 사이 다른 화면으로 옮겼으면 처음 그리기도 하지 않는다.
- 표: 시각 · 구분(배지) · 증가분 · 누적 · 설비상태 · 구간. 최신순, «더 보기» 200건씩. 구분 배지: 검출=err, 미관측구간=warn, 리셋=warn, 통신끊김=err, 통신복구=suc, 수집기시작=gray.
- 하단 안내: «검출기가 센 검출(리젝트) 수를 수집 PC 시계 기준으로 자동 기록합니다. 시편(Fe 2.5 · SUS 4.0 mm) 감도 확인은 작업자가 CCP-1P 일지에 기록합니다(병행). 생산수량은 검출기가 0 으로 보고해 쓰지 않습니다.»
- CCP-1P 일지: 격자 화면 위에 **읽기 전용 참고 줄** «자동 검출 기록 오늘 N건 · 모니터링 공백 M분 [현황 보기]» (읽지 못한 행이 있으면 «· 읽지 못한 행 N건», 연결 판단 불가면 «· … 현재 연결 확인 불가» 를 덧붙인다). 비동기로 채우고 실패해도 일지 렌더를 막지 않는다. 읽는 사이 일지가 다시 그려졌으면 새 요소에 채운다. **일지 칸(통과량·검출량·판정)은 자동으로 채우지 않는다.**
- 진입: 더보기 메뉴 항목 «금속검출 실시간현황» (모든 역할 조회 전용). 하단 탭 매핑 `metal-live → more`.
- 꼬리표: 화면의 순수 로직은 `/* ── 금속검출 실시간현황 (NMD-530) ── */` ~ `/* ── 끝: 금속검출 실시간현황 ── */` 마커 사이에 둔다(테스트가 이 구간을 떼어 돌린다).
- 테마는 CSS 변수만(`--pri --suc --warn --err --gray-l --txt-l …`). 헥스 하드코딩 금지. 터치 대상 최소 44px.
